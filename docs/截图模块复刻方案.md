# ZMENG 截图模块复刻方案（去 snow-shot 化路线图）

> 目标：让 ZMENG 成为一个**不依赖 snow-shot 官方服务、可自主开源发布**的全能剪贴板 + 截图 + 翻译工具。
> 本文回答两个问题：① 现在开源会有什么版权问题；② 如何分阶段把上游依赖替换为自有实现。

---

## 一、现状盘点：ZMENG 里到底什么是「别人的」

### 1. 代码层面

| 部分 | 来源 | 许可证 | 开源发布约束 |
|---|---|---|---|
| 截图/标注/OCR/翻译器/设置页等主体代码 | snow-shot 0.7.9-beta（mg-chao）原地扩展 | 双许可：**非商业 = Apache-2.0**；**商业 = GPL-3.0** | 非商业开源发布可行（需保留版权声明、声明修改）；商用需 GPL-3.0 兼容或商业授权 |
| ZMENG 新增代码（剪贴板侧栏、AI 面板、托盘、设置统一页等） | 自研 | 自有 | 无约束，可任意选择许可证 |
| xcap（屏幕采集，mg-chao fork） | Apache-2.0 | Apache-2.0 | 可随包分发 |
| windows-capture（HDR 采集） | MIT | MIT | 可随包分发 |
| paddle-ocr-rs + ort（本地 OCR 推理） | MIT | MIT | 可随包分发 |
| Excalidraw（标注画布，@mg-chao fork） | MIT | MIT | 可随包分发 |
| qr-scanner-wechat | MIT | MIT | 已本地打包 |

### 2. 模型/二进制层面

| 资产 | 来源 | 许可证 | 说明 |
|---|---|---|---|
| RapidOCR 四个 ONNX 模型（det/cls/rec ×2） | PaddleOCR 系（Apache-2.0） | Apache-2.0 | **0.0.9 起已随包分发**（`src-tauri/models/`），不再从 snowshot.top 下载 |
| ffmpeg.exe | 插件下载 | LGPL（若用 LGPL 构建） | 目前走「插件目录 → 随包 models 目录 → 系统 PATH」三级回退；若日后随包分发需选 LGPL 构建并在文档声明 |

### 3. 运行时网络依赖（snowshot.top）

| 依赖 | 0.0.9 状态 |
|---|---|
| 官方翻译接口（有道/DeepSeek/通义） | **已移除**。翻译只走用户自配 LLM（momo 中转站 MiniMax-M2）+ DeepL 自定义 |
| 官方模型列表（/api/v1/chat/models） | **已移除**。AiPanel/视觉模型/翻译服务列表仅显示用户自配后端 |
| OCR 模型下载 | 随包本地播种优先，在线下载仅作回退 |
| ffmpeg 插件下载 | 随包/PATH 回退（见上） |
| qr-scanner CDN | **已移除**，改为本地打包 |
| 更新检查 | 占位域名，未启用 |

**结论：0.0.9 起 ZMENG 已无任何 snowshot.top 强运行时依赖（复刻阶段一完成）。**

## 二、版权结论（能否开源？）

- **可以开源**，前提是遵守上游 snow-shot 的**非商业 Apache-2.0** 条款：
  1. 保留上游版权声明与 LICENSE 文件（`LICENSE-NonCommercial`）；
  2. 在 README/NOTICE 中显著声明「基于 mg-chao/snow-shot 二次开发并修改」；
  3. 不以该衍生版本直接商用（商用需 GPL-3.0 开源整个应用，或联系上游取得商业授权）。
- 若希望**完全无顾虑**（含商用自由），需把 snow-shot 自有代码部分替换为自研实现——即本方案的阶段二~四。
- ⚠️ momo 中转站的 API Key 目前写在前端默认配置中，**开源前必须先换成占位符**。

## 三、复刻路线（五阶段）

### 阶段一：去官方依赖（✅ 已于 0.0.9 完成）
见上表。核心改动：翻译引擎自包含、OCR 模型随包、ffmpeg 多级回退、QR 本地化。

### 阶段二：采集层 clean-room 重写（工作量：约 1~2 周）
用 `windows` crate 直接实现，替换 xcap fork 调用面：
- DXGI Desktop Duplication（SDR 常规采集，逐帧拷贝改为 ID3D11 staging 纹理直读）；
- Windows.Graphics.Capture（HDR/独占全屏，复用现有 windows-capture 依赖）；
- 多显示器枚举与虚拟桌面坐标（负坐标、混合 DPI）自持，输出统一 `ElementRect`。
- 验收口径：与现有 `MonitorList::capture` 接口签名兼容，前端零改动。

### 阶段三：标注 UI 自研重写（工作量：约 2~4 周，是最大头）
用 React + Canvas 自研标注组件替换 snow-shot 的 draw 页（保留窗口管理与选区框架）：
- 必备工具：矩形/椭圆/箭头/画笔/文字/序号钉/马赛克/高亮/橡皮/撤销重做；
- 交互：选区八向拖拽、放大镜取色、快捷键与工具栏；
- Excalidraw 高级标注（自由画布）可继续使用（MIT 无约束）。
- 策略：新组件与旧 draw 页并存，按功能开关切换，逐工具迁移，稳定后删除旧页。

### 阶段四：翻译器/设置页去遗留化（工作量：约 3~5 天）
- 删除旧版 functionSettings/generalSettings 等遗留路由与 i18n；
- 翻译器（translator 组件）UI 重写为 ZMENG 风格，逻辑已自包含；
- 清理 snow-shot 品牌文案与无用类型。

### 阶段五：许可证切换与仓库治理（工作量：约 1~2 天）
- 自研占比达标后，为自有代码选定许可证（建议 GPL-3.0 以兼容上游商业条款，或保持 Apache-2.0 仅非商业）；
- 建立 `NOTICE`/`THIRD_PARTY` 文件：上游 snow-shot、xcap、windows-capture、paddle-ocr-rs、ort、excalidraw、ffmpeg(LGPL)、RapidOCR 模型(Apache-2.0)；
- CI 校验：禁止新增对 snowshot.top 的引用（grep 门禁）。

---

## 四、风险与建议

1. **不建议一次性重写**：snow-shot 的 draw 页交互细节（选区/吸附/放大镜）打磨多年，逐工具迁移 + 开关灰度最稳。
2. 采集层重写优先级最高（双屏/掉帧问题都在这一层，且当前已修的索引 bug 属于该层）。
3. 开源前 checklist：换掉 momo key、保留上游 LICENSE、添加 NOTICE、确认 ffmpeg 许可声明。
